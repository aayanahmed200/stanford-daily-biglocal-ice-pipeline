Data pipeline

Reading 965 ICE press releases as data

A rules-based extractor that turns narrative press releases into structured records, and a validator that says which records are fit to report from.

Aayan Ahmed · Big Local News ICE dataset · Python

965 public press releases in the source dataset
6 fields extracted per release, from dateline to action type
8 validation checks on schema, completeness and sanity
HTML parsed from the original source, so future releases can be run too

Press releases are written to be read, not counted. The useful facts in them — where an action happened, which agency ran it, whether money or a headcount is involved — sit inside sentences that vary from release to release, which is why a pipeline that works on this corpus has to be re-runnable rather than a one-off scrape.

This one works from the raw HTML of each release in three stages. Extract pulls the dateline location, named people where they are stated, agencies mentioned, money amounts, quantities, and a broad action category; sentence patterns locate the people, and text cues separate action types where the dataset's own labels are too broad to be useful. Validate then checks the schema, field completeness, duplicate URLs, body length, out-of-range ages and unparseable dates. Report writes both a tidy CSV for analysis and a markdown validation report, so a record that failed a check is visible rather than silently dropped.

The validation step is the part that makes the output safe to use. On a five-row smoke test of the pipeline, schema checks passed and dates parsed cleanly, while one record had a near-empty body and one date could not be parsed — 4 of 5 records usable. Those numbers describe the smoke test, not the full corpus; the full run writes its own report.

Before publishing anything from this. The extractor is pattern-based, so a field can be confidently wrong. Every record is meant to be checked against its original press release before it appears in a story; the validation report flags which records are weakest, not which are correct.
